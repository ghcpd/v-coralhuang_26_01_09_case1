## Context

The legacy SDK exposes:

```python
sdk.Charge.create(amount, currency, source)
```

When:

```python
LegacyStripeSDK.VERSION >= "2022-11-15"
```

the Charges endpoint is removed at runtime and raises:

```
RuntimeError("endpoint removed")
```

The new SDK exposes:

```python
sdk.PaymentIntent.create(
    amount,
    currency,
    payment_method,
    capture_method
)
```

This introduces request contract drift and a different response schema.

## Behavior & Migration Details 💡

- Legacy flow:
  - If `sdk.Charge` exists, `PaymentClient.pay` attempts `Charge.create(...)`.
  - A trace line is appended: `[legacy] Charge.create invoked`
- Runtime removal:
  - If `Charge.create` raises `RuntimeError("endpoint removed")`, the client logs `[error] endpoint removed` and *automatically falls back* to `sdk.PaymentIntent.create(...)` if available.
  - Trace lines appended: `[fallback] Switching to PaymentIntent.create` and `[v2] PaymentIntent.create invoked`
- v2-only SDK:
  - If `Charge` is absent but `PaymentIntent` exists, the client calls `PaymentIntent.create(...)` directly and logs `[v2] PaymentIntent.create invoked`
- Request mapping & normalization:
  - `source` → `payment_method`
  - `capture_method="automatic"` is applied for PaymentIntent requests
  - Normalized response:
    - `id`: `latest_charge` when present (v2), otherwise `id` (legacy)
    - `amount`, `currency`, `status` normalized consistently
